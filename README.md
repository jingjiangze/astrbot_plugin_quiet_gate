# 表情暂存 · astrbot_plugin_quiet_gate

> **表情是情绪，不是信息。**
> 只发表情时先按住不说，等对方把话说完，再带着那股情绪回。

AstrBot 插件 · 需要 `astrbot >= 4.29.0` · GPL-3.0-or-later

---

## 1. 它解决什么问题

群聊里最常见的两连发：

```
A: 😭
A: 我今天面试又挂了
```

| 机器人的做法 | 结果 |
|---|---|
| 对 `😭` 单独回一句「怎么啦？」 | 抢话、显得急，而且猜错了重点 |
| 把 `😭` 当噪音丢掉 | 回「面试挂了」时完全不知道对方正在难过 |
| **本插件** | 先记住「他现在是难过」，等那句话来了再一起回 |

同理反过来也成立：对方发 `😂` 然后说「我过了」，机器人要能读出「这是如释重负」而不是平铺直叙地祝贺。

## 2. 行为规则

一条消息进来，按顺序判断：

```
含 @机器人               → 正常处理（不暂存）
去掉标点/emoji/[表情]后还有文字 → 正常处理（不暂存）
其余（纯表情/纯贴纸/纯图片/纯标点空白）→ 暂存情绪，本次不回复
```

暂存后：

```
同一用户 TTL 内发来文字  → 情绪作为背景注入这次回复 → 消费掉暂存
TTL 到期还没等到文字     → 静默丢弃（不追问、不补回）
```

**关键点：只拦这一次 LLM 请求，不中断事件流。**
用的是 `on_llm_request` + `event.stop_event()`，所以表情包采集、图搜、解析等其它插件照常收到这条消息。

## 3. 效果示例

配置 `profile_min_samples: 5`，某用户攒了 5 个表情之后：

```
用户: 😭
用户: 我今天面试又挂了

注入的 system_prompt 追加片段：
（对方刚才先发了表情、没有文字，情绪倾向：难过，距今 8 秒。
 表情通常只表达情绪、不是信息；请结合他这一句文字来理解，不要就表情本身追问。）
（此人的表情历史以 大笑×3、难过×2 为主，可据此判断他的表达习惯）
```

机器人于是不需要对表情做单独回应，也不会把面试挂掉这件事说得轻飘飘。

## 4. 安装

**方式一（推荐）**：AstrBot 面板 → 插件市场 → 从仓库安装

```
https://github.com/jingjiangze/astrbot_plugin_quiet_gate
```

**方式二**：手动放入 `data/plugins/astrbot_plugin_quiet_gate/`，然后在面板重载插件。

无第三方依赖，纯标准库。

## 5. 配置项

面板 → 插件配置里可改，字段名与默认值：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enable` | bool | `true` | 总开关 |
| `ttl_seconds` | int | `120` | 暂存有效期（秒）。60~300 比较自然 |
| `profile_min_samples` | int | `5` | 画像样本门槛，不够就不注入表达习惯 |
| `max_pending_per_user` | int | `4` | 每人最多暂存几个表情（只保留最近的） |
| `private_enable` | bool | `true` | 私聊是否也生效 |
| `group_whitelist` | list | `[]` | 只在这些群生效，空 = 全部群 |
| `group_blacklist` | list | `[]` | 这些群不生效，优先级高于白名单 |
| `unknown_label` | string | `情绪不明` | 映射表里没有的表情标签 |
| `show_hint_to_user` | bool | `false` | 调试用，回复里回显识别结果 |

## 6. 命令

| 命令 | 权限 | 说明 |
|---|---|---|
| `/表情暂存` | 所有人 | 看自己当前暂存了几个表情、什么情绪、还剩多久失效 |
| `/表情画像` | 所有人 | 看自己的表情情绪统计 |
| `/表情画像清除` | 管理员 | 清空全部画像数据 |

## 7. 情绪是怎么识别的（不瞎猜）

| 来源 | 方式 |
|---|---|
| unicode emoji `😭😂😡👍…` | 内置可靠映射表，覆盖 40+ 常见 emoji |
| QQ 表情（`Face` 段，带 `id`） | 按 id 查表（best-effort） |
| 表里没有的 | **一律标 `unknown_label`（默认「情绪不明」）**，交给模型结合语境判断 |

映射表外置可改，改完重载插件生效：

```json
// data/plugin_data/astrbot_plugin_quiet_gate/emotion_map.json
{
  "qq_face": { "14": "难过", "178": "大笑" },
  "unicode": { "😂": "大笑", "😭": "难过" }
}
```

> 为什么不直接调 LLM 判情绪？为省一次调用、也为了避免「模型自己编一个情绪出来」——
> 宁可标「情绪不明」，让主模型在真正回复时结合上下文判断。

## 8. 数据文件

目录：`data/plugin_data/astrbot_plugin_quiet_gate/`

| 文件 | 内容 |
|---|---|
| `pending.json` | 暂存队列，`{会话\|用户: {items:[{emotions,at}], ts}}`；读写时自动清理过期项 |
| `profile.json` | 用户画像 `{sender_id: {counts, total, updated}}` |
| `emotion_map.json` | 可编辑的情绪映射表 |

读写都走 `asyncio.Lock` + 原子替换（写 `.tmp` 再 `os.replace`），并发下不会写坏。

## 9. 自己实验（推荐路径）

1. 装好插件，配置保持默认（`ttl_seconds=120`）
2. 群里**只发一个表情** → 应无回复
3. **5 秒内**发一句带文字的话 → 它会按那句话回，且语气对得上刚才的表情
4. 再试：只发一个表情，**等 3 分钟**再说话 → 这次不应带任何情绪背景（已失效）
5. 想看内部状态：`/表情暂存` 看队列、`/表情画像` 看统计
6. 想让它更啰嗦：把 `show_hint_to_user` 打开，回复末尾会带上本次识别结果
7. 想看日志：AstrBot 日志里搜 `[quiet_gate]`

## 10. 已知边界

- 情绪映射是启发式的；QQ 表情 id 未收录时只能「情绪不明」，补 `emotion_map.json` 可提升准确率
- 暂存按「会话 + 发送者」隔离，**跨群不共享**
- 不理解表情图片本身的画面内容（那是视觉模型的职责）
- 不做「表情 → 自动回一个表情」那种互啄，本插件只管上下文，不说话
